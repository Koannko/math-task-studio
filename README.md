# Math Task Studio — Supabase edition

Статическое приложение HTML/CSS/JavaScript с общей базой задач Supabase.

## Возможности

- Ученики открывают каталог по ссылке без регистрации.
- Общий каталог опубликованных задач, поиск и фильтры по теме и сложности.
- Последовательные подсказки.
- Проверка ответа на сервере Supabase: правильный ответ не отправляется в браузер ученика.
- Разбор решения доступен после правильного ответа.
- Панель учителя с magic link для `kostyleva-2000@bk.ru`.
- Создание, редактирование, публикация, снятие с публикации и удаление задач.
- Прогресс ученика хранится локально в браузере; сами задачи общие для всех.

## Файлы

- `index.html` — страница приложения.
- `config.js` — публичный Supabase Project URL и publishable key, а также email учителя.
- `app.js` — интерфейс и вызовы RPC.
- `styles.css` — оформление.
- `supabase-setup.sql` — таблица, безопасные RPC-функции и стартовые задачи.
- `.gitignore` — исключает локальные секреты и служебные файлы.

## 1. Загрузка на GitHub

Распакуйте архив и загрузите **содержимое папки `math-task-studio`** в корень репозитория `Koannko/math-task-studio`. В корне репозитория должны лежать `index.html`, `app.js`, `config.js`, `styles.css`, `README.md`, `.gitignore` и `supabase-setup.sql`.

## 2. Настройка базы Supabase

1. Откройте проект Supabase: https://supabase.com/dashboard/project/vegwgwotbhmsveawfxkd
2. Перейдите в **SQL Editor → New query**.
3. Откройте файл `supabase-setup.sql`, скопируйте его целиком в SQL Editor и нажмите **Run**.
4. Убедитесь, что скрипт завершился без ошибок. Появятся три опубликованные демонстрационные задачи.

## 3. Включение входа учителя

1. В Supabase откройте **Authentication → Providers → Email** и включите Email OTP / Magic Link.
2. Убедитесь, что разрешён вход по email. Если в проекте отключено создание пользователей, заранее пригласите `kostyleva-2000@bk.ru` через Authentication → Users.
3. После публикации сайта откройте **Authentication → URL Configuration**. Укажите полный адрес сайта GitHub Pages в **Site URL** и **Redirect URLs**, например `https://koannko.github.io/math-task-studio/`. Используйте фактический URL, который покажет GitHub Pages.
4. Если Supabase требует SMTP для отправки писем, настройте собственный SMTP в настройках Auth.

## 4. Публикация сайта GitHub Pages

1. В репозитории откройте **Settings → Pages**.
2. В Build and deployment выберите **Deploy from a branch**.
3. Выберите ветку `main` и папку `/(root)`, затем сохраните.
4. Дождитесь публикации и скопируйте выданный GitHub Pages URL.
5. Добавьте этот URL в Supabase URL Configuration, как указано выше.

## Безопасность

- `sb_publishable_...` — публичный ключ для браузера. Он не является секретом, но доступ к данным ограничивается правами и RPC.
- **Никогда не добавляйте `service_role` или `sb_secret_...` ключи в файлы сайта или GitHub.**
- Включён RLS, прямые права `anon` и `authenticated` на таблицу `tasks` отозваны.
- Все функции с `SECURITY DEFINER` используют пустой `search_path` и полностью квалифицированные имена таблиц; права на вызов ограничены.
- Публичные функции возвращают только опубликованные задачи и результат проверки. Поля `answer` и `tolerance` не выдаются ученику.
- Административные функции дополнительно проверяют текущую сессию Supabase и точное совпадение email учителя.

Проверка ответов доступна публично, поэтому её можно многократно вызывать. Для контрольных/экзаменационных сценариев позже стоит добавить rate limiting или CAPTCHA.

## Что пока не синхронизируется

История попыток и прогресс сохраняются в `localStorage` конкретного браузера. Общими являются задачи и их публикация. Синхронизацию прогресса между устройствами можно добавить отдельным этапом.
