# Math Task Studio — Supabase edition

Статическое приложение HTML/CSS/JavaScript с общей базой Supabase.

## Что работает в этой версии

- Общий каталог опубликованных задач: ученик открывает сайт по ссылке, без регистрации.
- Поиск и фильтры по теме и сложности.
- Последовательные подсказки.
- Проверка ответа через серверную RPC-функцию Supabase: правильный ответ не загружается в браузер ученика.
- Объяснение решения возвращается только после правильного ответа.
- Панель учителя с magic link для `kostyleva-2000@bk.ru`.
- Создание, редактирование, публикация, снятие с публикации и удаление задач.
- Прогресс ученика пока хранится локально в его браузере; база задач общая для всех устройств.

## Состав архива

- `index.html` — страница приложения и подключение Supabase JS.
- `config.js` — Project URL, publishable key и email учителя.
- `app.js` — интерфейс, работа с Supabase RPC и локальный прогресс.
- `styles.css` — оформление.
- `supabase-setup.sql` — схема базы, RPC-функции, права доступа и стартовые задачи.

## Установка Supabase (один раз)

1. Открой проект Supabase: https://supabase.com/dashboard/project/vegwgwotbhmsveawfxkd
2. Открой **SQL Editor → New query**.
3. Скопируй весь файл `supabase-setup.sql`, вставь в редактор и нажми **Run**.
4. Проверь, что запрос завершился без ошибок. В таблице `public.tasks` появятся три стартовые задачи.
5. Открой **Authentication → URL Configuration**.
6. В **Site URL** укажи адрес опубликованного приложения. Добавь этот же адрес (и локальный адрес разработки, если нужен) в **Redirect URLs**.
7. В **Authentication → Providers → Email** включи Email provider и Magic Link/Email OTP. Для реальной доставки писем настрой SMTP в **Project Settings → Authentication → SMTP Settings**; стандартная тестовая отправка Supabase имеет ограничения.
8. В **Authentication → Users** пригласи или создай пользователя `kostyleva-2000@bk.ru`. На этот адрес будут приходить ссылки входа.

## Публикация сайта

Загрузи содержимое папки `math-task-studio` в корень репозитория GitHub и включи GitHub Pages (**Settings → Pages → Deploy from a branch → main → /(root)**). Если сайт опубликован по адресу с путём, например `https://username.github.io/math-task-studio/`, добавь именно этот URL в Supabase Redirect URLs.

## Как пользоваться

- **Ученику:** открыть опубликованную ссылку и выбрать опубликованную задачу. Регистрация не требуется.
- **Учителю:** нажать «Учителю» → «Отправить ссылку для входа» → открыть письмо на `kostyleva-2000@bk.ru`. После перехода по magic link снова открыть вкладку «Учителю», если она не открылась автоматически.
- Созданные и опубликованные задачи сразу появляются в общем каталоге.

## Безопасность

- В `config.js` находится только Supabase Project URL и `sb_publishable` key. Это публичные клиентские параметры; их нельзя считать паролем.
- Не добавляй `service_role` key в файлы сайта и не отправляй его в браузер.
- RLS включён на `public.tasks`; прямые права `anon`/`authenticated` на таблицу отозваны. Чтение и запись доступны только через RPC-функции.
- `list_published_tasks()` отдаёт ученику только условие, тему, сложность и подсказки. Поля `answer` и `tolerance` не выдаются.
- `check_task_answer()` сравнивает ответ на сервере и возвращает только `correct` и, при успехе, объяснение.
- Административные RPC проверяют email текущей Supabase-сессии на точное совпадение с `kostyleva-2000@bk.ru`.

Важно: проверка скрывает ответы от обычного просмотра API, но публичную функцию проверки можно многократно вызывать. Для высокорисковых экзаменов или ценных заданий дополнительно понадобится ограничение частоты запросов (например, через Edge Function с rate limiting/CAPTCHA).

## Что пока не синхронизируется

Прогресс и история попыток хранятся в `localStorage` конкретного браузера. Общими являются сами задачи и их публикация. Синхронизацию ученического прогресса между устройствами можно добавить отдельным этапом — для этого потребуется продумать анонимные идентификаторы/профили и политику хранения данных.
